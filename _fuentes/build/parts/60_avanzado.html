Inducción y esquemas

La inducción no cabe en la lógica de primer orden: habla de «cualquier propiedad». Mizar la expresa con esquemas, teoremas cuyos parámetros son predicados o funciones.

Qué es un esquema

Un teorema cuantifica sobre objetos. Un esquema tiene además parámetros que son predicados, escritos con corchetes (P[…]), o functores, escritos con paréntesis (F(…)). El de inducción es NAT_1:sch 2:

scheme :: NAT_1:sch 2 NatInd { P[Nat] } : for k being Nat holds P[k] provided P[0] and for k be Nat st P[k] holds P[k + 1];

Se lee: para cualquier propiedad P de los naturales, si se cumplen las dos premisas (después de provided), entonces vale la conclusión.

Usar la inducción

Tres ingredientes: definir el predicado con defpred, demostrar las dos premisas y aplicar el esquema con from. En la definición del predicado, $1 representa su argumento.

theorem Gauss: s.0 = 0 & (for n holds s.(n + 1) = s.n + (n + 1)) implies for n holds s.n = n*(n + 1)/2 proof assume that A1: s.0 = 0 and A2: for n holds s.(n + 1) = s.n + (n + 1); defpred P[Nat] means s.$1 = $1*($1 + 1)/2; A3: P[0] by A1; A4: for k st P[k] holds P[k + 1] proof let k; assume P[k]; then s.(k + 1) = k*(k + 1)/2 + (k + 1) by A2; hence thesis; end; thus for n holds P[n] from NAT_1:sch 2(A3,A4); end;

Aquí s es una sucesión real (reserve s for Real_Sequence) dada por recurrencia: s(0) = 0 y s(n+1) = s(n) + (n+1), es decir, s(n) = 1 + 2 + … + n. El teorema es la suma de Gauss.

Cuidado

En el paso que lleva from, y en las premisas que se le pasan, el predicado tiene que aparecer escrito como P[…]: Mizar empareja textualmente con el esquema. Por eso A3 dice P[0] y no s.0 = 0*(0 + 1)/2. En todo lo demás, P[k] y su significado son intercambiables: el verificador lo despliega al instante.

La potencia con exponente natural se escribe x |^ n, y sus dos hechos básicos son NEWTON:4 (z|^0 = 1) y NEWTON:6 (z|^(s+1) = z|^s * z). Con ellos se demuestran por inducción desigualdades como n < 2|^n o la de Bernoulli; están en el archivo de ejercicios.

deffunc y la construcción de objetos

deffunc es a los functores lo que defpred a los predicados: una fórmula local con nombre. Sirve para los esquemas que construyen funciones. Por ejemplo SEQ_1:sch 1 dice que existe la sucesión cuyo término general es una fórmula dada:

deffunc F(Nat) = $1*($1 + 1)/2; consider s such that A1: for n holds s.n = F(n) from SEQ_1:sch 1;

Con esto se demuestra que la sucesión de la que habla el teorema de Gauss existe de verdad. Así se definen en Mizar las funciones «por una fórmula»: no hay notación lambda, hay esquemas de existencia.

Esquemas propios

Un esquema se enuncia y se demuestra como un teorema. Los parámetros van entre llaves y las premisas después de provided:

scheme IndDesde1 { P[Nat] } : for n st 1 <= n holds P[n] provided A1: P[1] and A2: for k st 1 <= k & P[k] holds P[k + 1] proof defpred Q[Nat] means 1 <= $1 implies P[$1]; A3: Q[0]; A4: for k st Q[k] holds Q[k + 1] proof let k; assume A5: Q[k]; assume 1 <= k + 1; per cases by NAT_1:14; suppose k = 0; hence P[k + 1] by A1; end; suppose A6: 1 <= k; then P[k] by A5; hence P[k + 1] by A2,A6; end; end; for n holds Q[n] from NAT_1:sch 2(A3,A4); hence thesis; end;

Es la inducción que empieza en 1, demostrada a partir de la que empieza en 0. Dentro del mismo artículo el esquema se cita por su nombre: from IndDesde1(A1,A2).

Conjuntos por comprensión y cardinales

El operador de Fraenkel escribe conjuntos «de todos los … tales que …». Con él se demuestra el teorema de Cantor, y de ahí se pasa a contar.

El operador de Fraenkel

{ n where n is Nat : 3 < n } { 2*k where k is Nat : k <= 10 } { x where x is Element of X : not x in f.x }

La forma general es { término where variables : condición }. Corresponde al axioma de reemplazo de Fraenkel, la F de ZF. Hay una restricción: los tipos de las variables deben tener como extensión un conjunto (Nat, Real, Element of X…). No vale set ni object, porque entonces se podría escribir el conjunto de Russell { X where X is set : not X in X }.

Lo cómodo es que el verificador sabe entrar y salir de estos conjuntos sin que se cite nada:

theorem 5 in {n where n is Nat : 3 < n}; theorem x in {n where n is Nat : 3 < n} implies ex n being Nat st x = n & 3 < n;

Para entrar basta exhibir el elemento y que cumpla la condición. Para salir, de x in { … } se obtiene un ex, que normalmente se aprovecha con consider. Como estas expresiones son largas, se les da nombre con set:

set Pares = {n where n is Nat : ex k being Nat st n = 2*k};

El teorema de Cantor

Ninguna función de X en sus partes es sobreyectiva. La demostración clásica usa el conjunto diagonal D = {x ∈ X : x ∉ f(x)}, que es un Fraenkel:

theorem Cantor: for X being non empty set, f being Function of X, bool X holds rng f <> bool X proof let X be non empty set, f be Function of X, bool X; set D = {x where x is Element of X : not x in f.x}; A1: D c= X proof let z; assume z in D; then ex x being Element of X st z = x & not x in f.x; hence z in X; end; assume rng f = bool X; then D in rng f by A1,ZFMISC_1:def 1; then consider a being object such that A2: a in dom f and A3: f.a = D by FUNCT_1:def 3; reconsider a as Element of X by A2; per cases; suppose A4: a in D; then ex x being Element of X st a = x & not x in f.x; hence contradiction by A3,A4; end; suppose A5: not a in D; then not a in f.a by A3; then a in D; hence contradiction by A5; end; end;

Si D fuera f(a) para algún a, entonces a ∈ D si y sólo si a ∉ D. Es la paradoja de Russell de la lección 5, ahora con un uso honrado. Fíjate en reconsider a as Element of X: sin nombre nuevo, el propio a cambia de tipo.

Cardinales finitos

card A es el cardinal de A. Si A tiene tipo finite set, los registros de la MML hacen que card A sea un número natural, y se puede operar con él.

A misses B significa que son disjuntos. Con estos hechos sale, por ejemplo, el principio del palomar: si f : A → B y B tiene menos elementos que A, f no es inyectiva.

theorem Inyeccion: for B being non empty finite set, f being Function of A,B st f is one-to-one holds card A <= card B proof let B be non empty finite set, f be Function of A,B; assume f is one-to-one; then A1: card dom f = card rng f by CARD_1:70; A2: dom f = A by FUNCT_2:def 1; card rng f <= card B by NAT_1:43; hence thesis by A1,A2; end; theorem Palomar: for B being non empty finite set, f being Function of A,B st card B < card A holds not f is one-to-one by Inyeccion;

Para conjuntos infinitos, tener el mismo cardinal es que exista una biyección: X,Y are_equipotent iff card X = card Y (CARD_1:5). Entre cardinales, «menor» se escribe in, y la versión de la MML del teorema de Cantor es card X in card bool X (CARD_1:14).

Estructuras

Un grupo es un conjunto con una operación. Las estructuras permiten tratar ese paquete como un solo objeto, y son lo que da a la MML su sabor abstracto.

Registros con campos

Una estructura es un objeto con campos con nombre. La más simple de la MML tiene uno solo, y la de los magmas dos:

struct 1-sorted (# carrier -> set #); struct (1-sorted) multMagma (# carrier -> set, multF -> BinOp of the carrier #);

Los campos van entre (# y #). Entre paréntesis, antes del nombre, van las estructuras antepasadas: multMagma hereda de 1-sorted, y todo multMagma se puede usar donde se espera un 1-sorted. Un campo se lee con the campo of S:

a*babreviatura de (the multF of G).(a,b)

Los grupos de la MML

Un grupo no es una estructura nueva, sino un multMagma con adjetivos:

mode Group is Group-like associative non empty multMagma;

Cada adjetivo es un atributo definido en GROUP_1: associative es la asociatividad y Group-like la existencia de neutro e inversos. A partir de ellos se definen el neutro 1_G y el inverso a". Los axiomas se citan así:

reserve G for Group; reserve a,b,c for Element of G; theorem (a*b)*c = a*(b*c) by GROUP_1:def 3; theorem a*1_G = a & 1_G*a = a by GROUP_1:def 4; theorem a*a" = 1_G & a"*a = 1_G by GROUP_1:def 5;

En un grupo abstracto el verificador no sabe aritmética: no hay ARITHM que valga. Cada reagrupamiento se justifica con la asociatividad, y las cuentas se escriben como igualdades iteradas:

theorem InvProd: (a*b)" = b"*a" proof (a*b)*(b"*a") = a*(b*(b"*a")) by GROUP_1:def 3 .= a*((b*b")*a") by GROUP_1:def 3 .= a*(1_G*a") by GROUP_1:def 5 .= a*a" by GROUP_1:def 4 .= 1_G by GROUP_1:def 5; hence thesis by GROUP_1:12; end;

GROUP_1:12 dice que si h*g = 1_G entonces h = g" y g = h".

Dos estilos

También se puede demostrar un hecho de grupos sin estructuras: se toma un conjunto G, una BinOp of G, un elemento y una función inverso, y se ponen los axiomas como hipótesis. Es más directo para un teorema suelto. Las estructuras rinden cuando se construye teoría: los adjetivos se acumulan (grupo, grupo conmutativo, anillo, cuerpo…) y los registros y teoremas se heredan.

Una estructura propia

Los nombres de estructura y de campo son símbolos de vocabulario (letras G y U).

definition struct (1-sorted) Punteado (# carrier -> set, base -> Element of the carrier #); end; theorem ex P being Punteado st the carrier of P = NAT & the base of P = 0 proof reconsider z = 0 as Element of NAT by ORDINAL1:def 12; take Punteado(# NAT, z #); thus thesis; end;

El campo base tiene un tipo que depende de otro campo. Para construir el objeto, el 0 debe tener exactamente el tipo Element of NAT: de ahí el reconsider.
